# Architecture
- **Modular monolith** (`apps/api/src/modules/*`): auth, merchant/onboarding, admin, payments, providers, ledger, webhooks, jobs/recon. API and worker (`src/worker.ts`) are separate processes sharing the codebase.
- **Canonical API**: merchants call `/v1/payins|payouts|refunds` in SyntrixAPI shapes (integer paise). `ProviderAdapter` (`providers.ts`) translates to each upstream; `provider_capabilities` is the matrix — unsupported operations are rejected, never faked.
- **Money**: `BigInt` paise in Postgres, integer math in code, never floats. Double-entry ledger: every posting is balanced, immutable (no update/delete paths), balances are derived by summing entries.
- **Correctness**: unique `(merchantId, env, merchantRef)`, `IdempotencyRecord` (same key+payload → cached response; different payload → 409), serializable payout hold (balance check + debit in one transaction), state machine `PENDING→PROCESSING→SUCCESS/FAILED/UNKNOWN` where terminal states never regress and `UNKNOWN` resolves **only** via status check/reconciliation — payouts are never blindly retried or provider-switched.
- **Outbox**: state changes write `outbox_events` in the same DB transaction; the worker relays them and delivers merchant webhooks (HMAC `t=,v1=`, exponential backoff, 5 attempts → `DEAD_LETTER`, manual replay). Incoming provider webhooks are persisted (unique provider event id) **before** ack; duplicates are no-ops.
- **Tenancy**: JWT cookie session → membership → `merchantId`; merchant queries are always scoped by it; `assertTenant` + role/permission guard (`@syntrix/shared` PERMISSIONS) on every route. Staff roles are platform-scoped.
- **Secrets**: provider credentials + webhook secrets AES-256-GCM encrypted (key from `ENCRYPTION_KEY`, ideally KMS in prod); API keys stored as SHA-256 hashes, full secret shown once; PAN/bank numbers encrypted; logs redact secret-like fields.
