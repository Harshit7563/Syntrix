# Deployment model (current: PERSONAL MODE)
Yeh installation single-owner personal aggregator hai: ek hi downstream portal SyntrixAPI ko API key se call karta hai, aur SyntrixAPI multiple upstream APIs ko integrate/switch karta hai. Multi-merchant onboarding code maujud hai lekin PERSONAL_MODE=true mein owner login se saare provider/switch/key controls ek hi panel mein milte hain. Doosre merchants ko API dena ho to PERSONAL_MODE=false karke full SaaS mode use karo.

# Implemented vs. production prerequisites
## Implemented (mock mode)
Auth (bcrypt, HttpOnly cookies, refresh-session revocation, admin MFA/TOTP), 7 roles + permission guard + tenant isolation, guided onboarding (draft, progress, projected-vs-actual volumes, encrypted PAN/bank, private doc upload with type/size validation + expiring links, clarification loop, sandbox/production split), admin review + document verification + approval history, maker-checker queue, provider registry (encrypted creds, capabilities, SSRF allowlist), products/access/pricing/routing, API keys (hash-only, rotate/revoke, IP allowlist), canonical pay-in/payout/refund over **MockPay**, idempotency, serializable payout holds, double-entry ledger, usage/invoices, signed merchant webhooks (retry/backoff/DLQ/replay), provider webhook intake (persist-before-ack, dedupe, out-of-order safe), outbox worker, status sweep + reconciliation, audit log, CSV export, Swagger, Postman collection, Docker Compose, unit tests.

## NOT production-ready until you add
Real provider contracts + reseller authorization & adapters (docs/PROVIDER_INTEGRATION.md), real OTP/verification providers (KYC/PAN/GST/bank penny-drop), malware scanning service, managed PG/Redis/S3 + KMS, CSRF tokens for cookie mutations in prod (SameSite is set; add token for strict posture), rate-limit store in Redis (per-merchant/product), full BullMQ queue wiring in the worker (outbox poller included as durable fallback), observability (metrics/tracing/alerting), penetration test, load tests, and compliance/legal sign-off (PCI scope: never store card data; payments must stay with licensed providers).
